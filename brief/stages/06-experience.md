# Stage 06 — complete usable experience

## Build

Finish navigation and the Dashboard, Feedback & Targets, Study Plan, Progress and
Settings workflows. Use simple cards, clear labels, short forms and expandable details.
Avoid the previous diagnostic screen's editable source/confidence/scoring-basis fields.
Show what to practise, why it is scheduled, and what to do when it cannot fit.

Add source-labelled practice history, actual versus planned time and clearly defined
completion figures without double-counting missed/replacement attempts. Separate
priority trends from reported difficulty. Derive reports from the real records.
Use local assets and straightforward charts only when they help.

Implement optional PDF attachments for reference with size/type checks, safe storage,
owner-only serving and no OCR. Keep uploaded content outside public static paths;
never execute it. All essential flows remain possible without uploading a file.

Add understandable empty/error/overdue/locked-conflict states, confirmation for genuinely
destructive actions, keyboard-accessible forms and narrow-screen layouts. Do not claim
formal accessibility compliance without the corresponding evaluation.

## Gate

Browser tests exercise all main actions, fresh onboarding and empty states. Test secure
attachment retrieval, invalid uploads, progress arithmetic, mobile overflow and fatal
console errors. Save readable screenshots of major screens and inspect them using
available visual tools; record if visual inspection itself was unavailable. No required
button is a placeholder or hidden behind unavailable credentials.
